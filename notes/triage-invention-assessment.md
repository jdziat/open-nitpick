Ship **A (Shrink) as immediate containment, combined with a proposed mechanical “no new claims” contract for triage**; keep B experimental and do not ship C as an invention-elimination fix. A already removes the model call when triage receives no findings and grounding is off (`internal/review/engine.go:1421`). None of A, B, or C alone eliminates invention across triage: the existing findings check permits new claims on an allowed path, and summary text is returned without an evidence check (`internal/review/engine.go:1491`, `internal/review/engine.go:1565`). The proposed contract would render summaries from verified structural facts and let triage select existing finding IDs without authoring replacement claims. This is a design recommendation, not an implemented change.

Option C's soundness and what breaks

C has a useful locality property: its first author sees the batch's diff. It nevertheless introduces a lossy intermediate account of the change. A downstream triager cannot recover omitted context or distinguish a faithful summary from an invented one merely by reading it. Giving it both summaries and findings also does not enforce which source supplies the walkthrough. These are design limitations of the proposed information flow, not evidence of improved accuracy.

- **Required-summary omission on weak models.** Do not make descriptive prose a condition for retaining valid findings. Strict schema enforcement can make omission fail a response; JSON/text fallbacks do not enforce every required property locally. The local population check accepts any recognized field, so missing summary need not fail, and a summary-only response is another hazard because Summary already belongs to Result (`internal/llm/structured.go:293`, `internal/llm/structured.go:444`, `internal/llm/structured.go:517`, `internal/review/finding.go:203`). A final extraction error loses that reviewer's findings; a single-reviewer batch then fails, whereas an ensemble retains other successful reviewers (`internal/review/engine.go:1151`, `internal/review/route.go:202`). Failed batches are disclosed, and all batches failing aborts the run (`internal/review/engine.go:996`, `internal/review/engine.go:1019`). Recommendation: make summary optional, accept valid findings independently, explicitly require a usable findings payload, and use deterministic summary fallback without a prose-repair call. Validate omission, malformed-summary and summary-only responses across output modes before adoption.
- **Determinism under concurrent batches.** Appending summaries under a mutex would prevent a race but preserve completion order. Batches run concurrently and currently append findings that way; findings receive a later sort (`internal/review/engine.go:969`, `internal/review/engine.go:1002`, `internal/review/engine.go:1041`). Ensemble reviewers are concurrent too (`internal/review/route.go:178`). Recommendation: retain summaries by stable plan batch index, with a fixed reviewer priority and deterministic fallback for failed reviewers; concatenate only after completion. Do not select the first response to arrive. This guarantees assembly order for fixed outputs, not repeatable model prose.
- **Output length with many batches, including 60 files.** Defaults permit 60 files and six files per request, but token packing can force one file per batch (`internal/config/defaults.go:93`, `internal/bundle/bundle.go:505`). If all 60 selected files are reviewed, C's two sentences per batch means 20 sentences for ten full batches and up to 120 for sixty batches, before ensemble duplication. That is far beyond the present two-to-four-sentence walkthrough instruction (`internal/prompt/templates/triage.md:54`). Recommendation: choose one summary per batch, enforce a total byte/token allowance for both presentation and triage input, and disclose deterministic omission counts. Prefer a compact structural roll-up over calling another model to compress prose. Cap whole records rather than cutting sentences into misleading fragments.
- **Per-batch invention at smaller scale.** Yes: a model can invent intent, causal effects or whole-repository behavior while viewing a real diff. Review context can be windowed, and selected batches do not cover all skipped files (`internal/bundle/bundle.go:35`, `internal/bundle/bundle.go:84`, `internal/bundle/bundle.go:570`). Recommendation: describe only verified facts about the reviewed scope, preserve incomplete/skipped notices, and never equate zero findings with proven correctness. Ordinary free-form batch summaries remain an experiment, not the elimination mechanism.

Further integration decisions are necessary even for an experiment. The existing style pass reuses batch analysis, so it must not duplicate defect-pass summaries (`internal/review/engine.go:1086`). Ensembles need an explicit summary ownership rule rather than pooling all prose (`internal/review/route.go:166`). Advisory holdout means zero triage findings must not produce an unconditional clean verdict; the current code only adds its advisory note when a nonempty summary exists (`internal/review/engine.go:639`). Recommendation: retain report-derived notices independently of summary availability and distinguish unavailable summaries from failed reviews.

The guard that closes the gap

**C relocates invention; it does not eliminate it.** Concatenation avoids a model call on clean reviews but preserves whatever the batch models invented. Non-clean reviews add an opportunity to invent relationships between their summaries. Requiring citations or vocabulary overlap does not close this gap: a true excerpt can be attached to an unsupported claim, and a false sentence can use only words present in its source. The existing overlap metric cannot distinguish paraphrase from invention (`internal/evals/grounding_eval_test.go:78`, `docs/findings.md:1522`).

The proposed closing guard is **mechanical**, meaning computable without a model call, but it requires a narrower output contract. Permit only closed structural facts derived from the parsed change (path, change kind, additions and removals) and render them with fixed templates. Those inputs already support deterministic rendering (`internal/bundle/bundle.go:539`, `internal/bundle/bundle.go:544`). If a model selects records, validate every ID and derive all rendered values from the original records; reject unknown selections. Optional evidence excerpts must be checked byte-for-byte at the specified path, side and span and displayed as quotations, never promoted to behavioral conclusions. Fixed templates must not infer intent, safety or global effects from these records. The simpler alternative is to omit the walkthrough entirely.

Eliminating invention in the **whole triage step** also requires restricting findings output. Permit selection/grouping of original finding IDs and render the original title, rationale and suggestion unchanged; disallow novel prose, anchors and free-text merge explanations. Where elimination includes new severity claims, preserve severity too. Validate membership and allowed group structure mechanically; use deterministic deduplication if semantic merging is not worth the risk of incorrect grouping. This closes the current allowed-path loophole and avoids treating the existing location-tolerance accounting as semantic verification (`internal/review/engine.go:1491`, `internal/review/engine.go:1537`, `internal/review/engine.go:1572`). It prevents triage from introducing new factual claims; it does not certify upstream model findings as true. General behavioral truth would require a substantially richer formal specification/proof system or human assessment, and an additional model judge would still offer no elimination guarantee.

Ranking against elimination, rather than prose quality

1. **A:** First because its early return demonstrably removes one invention-producing call, though only for zero triage findings with grounding off (`internal/review/engine.go:1421`).
2. **B:** Second because it supplies primary diff evidence directly and avoids an intermediate model summary, but its generated output still passes the same inadequate semantic guards (`internal/review/engine.go:1384`, `internal/review/engine.go:1491`, `internal/review/engine.go:1565`).
3. **C:** Third because it would add an unverified batch narrative before non-clean triage synthesis, and the existing findings-only return path supplies no summary verification mechanism (`internal/review/engine.go:1151`, `internal/review/engine.go:1168`).

This ranking credits A's narrow, provable elimination and B's direct evidence; it is not a measured accuracy ranking between B and C. Only the proposed mechanical contract satisfies “no new claims from triage” across both summaries and findings. C could adopt that contract, but would then be a constrained structural reporting design rather than the proposed two-sentence generative approach.
